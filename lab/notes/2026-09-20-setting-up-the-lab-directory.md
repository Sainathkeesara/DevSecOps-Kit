# lab — setting up the directory

> First-day notes about turning `lab/` into a place I can revisit.

## What I checked

I opened the lab directory before changing anything. It already had a short primer, one environment config, and a `mini-projects/` area with a few separate practice setups. That told me the directory is meant to hold working examples, not just a pile of unexplained files.

## What I learned

The useful part of the setup is separation. I want a small config beside the note that describes it, and a dedicated folder when an example grows into several files. I also want every new experiment to say what it is trying to prove, so future-me does not have to guess from a filename.

I did not move the existing projects or rewrite the primer. This task was about understanding the layout, and changing working examples would make the directory harder to trust.

## What I'll do next

My next lab entry will stay in `lab/notes/` and describe one small setup attempt. If that attempt needs several files, I'll give it its own folder under `lab/mini-projects/` and link the idea back to the note.
